# Файл траектории полёта Земля — Луна (`trajectory-2026-11-15T120738Z.json`)

Описание для модели, которая будет работать с этим файлом: строить 3D-визуализацию,
анализировать полёт или переводить данные в другой формат.

Файл записывает программа **Lunch Window Prediction** (Rust, NASA Space Apps 2026,
«Lunar Landing Site Navigator»). Это один JSON-документ (не JSON Lines), ~1 МБ, формат
`lwp-trajectory/1`. Рядом лежит `flight-2026-11-15T120738Z.json` — журнал информации о
полёте (ракета, бюджет Δv, отчёты поиска); для 3D он не нужен.

## Системы координат и единицы

- **Все `r` и `v` — в J2000 (ICRF), начало в центре Земли.** Километры и км/с.
- **`r_moon`** — положение аппарата относительно центра Луны, **те же оси J2000** (не связанные с Луной).
  Есть только у точек рядом с Луной.
- **`moon_r`** — положение центра Луны относительно центра Земли, J2000, км. Есть в каждой точке,
  поэтому Луну можно двигать по сцене синхронно с аппаратом. Всегда `r_moon ≈ r − moon_r`.
- **`moon_v`** — скорость центра Луны относительно центра Земли, J2000, км/с (~1 км/с). Есть в каждой точке.
- **`v_moon`** — скорость аппарата **относительно центра Луны**, J2000, км/с. Есть у тех же точек,
  что и `r_moon`. Всегда `v = moon_v + v_moon`. **Это та скорость, которую надо показывать у Луны.**
- **Ориентация тел** — кватернион `[w, x, y, z]` поворота **из системы, связанной с телом, в J2000**:
  `v_J2000 = q · v_body · q⁻¹`. Обратный поворот (J2000 → тело) — сопряжённым кватернионом `[w, −x, −y, −z]`.
  - `earth_q` — Земля, система ITRF93 (вращение Земли, прецессия, нутация). Ось z — северный полюс,
    ось x — Гринвичский меридиан.
  - `moon_q` — Луна, система MOON_ME (DE440): ось z — северный полюс Луны, ось x направлена
    примерно на Землю (средняя точка видимого диска, 0° широты и 0° долготы).
- **Время:** `t` — строка UTC вида `"2026-12-29T05:24:12.229000000 UTC"` (ISO 8601 с наносекундами
  и суффиксом ` UTC`, без `Z`); `t_s` — секунды от старта (float). Для расчётов удобнее `t_s`.
- **Высоты в `start`/`end`/`landing_site`**: над эллипсоидом WGS84 для Земли и над сферой
  радиусом 1737,4 км для Луны. Высота места посадки −1,046 км — это нормально: рельеф ниже опорной сферы.

## Структура файла

```text
{
  "format": "lwp-trajectory/1",
  "created_utc": "...",
  "flight_log": "flight-2026-11-15T120738Z.json",   // соседний файл
  "frame", "units", "time", "quaternions": строки-пояснения (то же, что выше),
  "earth": { "radius_km": 6378.1363, "mu_km3_s2": 398600.435…, "orientation_frame": "ITRF93 …" },
  "moon":  { "radius_km": 1737.4,    "mu_km3_s2": 4902.800…,   "orientation_frame": "MOON_ME (DE440)" },
  "landing_site": { "lat_deg", "lon_deg", "height_km", "body_fixed_km": [x,y,z] },  // MOON_ME
  "notes": [ строки о моделях и шаге точек ],
  "trajectories": [ Trajectory, … ]      // здесь одна
}
```

`trajectories` — массив: при поиске по нескольким космодромам в нём может быть по варианту на
космодром. В этом файле один элемент.

### Trajectory

| Поле | Тип | Что это |
|---|---|---|
| `spaceport_id`, `spaceport_name` | string | `"ksc"`, `"Kennedy Space Center"` |
| `spaceport` | Site | широта, долгота, высота и `body_fixed_km` космодрома (ITRF93, эллипсоид WGS84) |
| `start` | Endpoint | начальная точка — стартовый стол в момент старта |
| `end` | Endpoint | конечная точка — касание в точке посадки |
| `source` | string | `"numerical"` — точки из численного интегрирования; `"none"` — точек нет |
| `unavailable_reason` | string? | почему точек нет (только при `source = "none"`) |
| `ascent_model` | string | `"simulation"` (численная модель ракеты по ступеням) или `"kinematic"` |
| `rocket` | string? | `"SLS Block 1 (ICPS)"` |
| `phases` | `[[phase, t_start_s, t_end_s], …]` | интервалы этапов |
| `events` | Event[] | ключевые события (12 штук) |
| `samples` | Sample[] | точки траектории (3465 штук), по возрастанию `t_s` |

### Endpoint (`start`, `end`)

```text
{ "event": "launch" | "touchdown" | …,  "body": "earth" | "moon",
  "t", "t_s", "lat_deg", "lon_deg", "height_km",
  "body_fixed_km": [x,y,z],   // ITRF93 для Земли, MOON_ME для Луны
  "r": [x,y,z],               // J2000 от центра Земли
  "r_moon": [x,y,z],          // только у конечной точки: J2000 от центра Луны
  "v": [vx,vy,vz] }
```

Если поиск нашёл перелёт без точки посадки, `end` — последнее событие у Луны (например `loi`),
а широта и долгота — подспутниковая точка под аппаратом.

### Sample (точка траектории)

| Поле | Есть | Что это |
|---|---|---|
| `t`, `t_s` | всегда | момент |
| `phase` | всегда | этап (см. ниже) |
| `r`, `v` | всегда | положение и скорость, J2000 от центра Земли |
| `moon_r` | всегда | центр Луны от центра Земли |
| `moon_v` | всегда | скорость центра Луны относительно центра Земли |
| `r_moon` | у Луны | аппарат от центра Луны (J2000); в `transfer` — в пределах 70 000 км от Луны |
| `v_moon` | у Луны | скорость аппарата относительно центра Луны (J2000); там же, где `r_moon` |
| `earth_q` | `ascent`, `parking_orbit` | ориентация Земли |
| `moon_q` | `lunar_orbit` и дальше | ориентация Луны |

Где кватерниона нет, его можно взять из ближайшего события (у событий оба кватерниона всегда есть)
или вычислить вращение самому (см. «Рецепты»).

### Event (событие)

```text

  "r", "v",              // v — скорость ПОСЛЕ события (после импульса)

  "moon_r", "moon_v",    // центр Луны и его скорость относительно Земли

  "earth_q", "moon_q",   // всегда оба

## Важные особенности

0. **Скорость у Луны — только `v_moon`.** `v` — скорость относительно центра Земли. На
   окололунной орбите она качается от ~0,6 до ~2,6 км/с с каждым витком (период ~118 мин):
   орбитальные 1,63 км/с то складываются со скоростью самой Луны (~1 км/с), то вычитаются.
   Это не ошибка в данных, а другая система отсчёта. Относительно Луны на орбите скорость
   ровная: 1,633–1,635 км/с. На эллипсе спуска она плавно растёт до 1,69 км/с, на торможении
   падает до нескольких м/с. Если вам нужна скорость относительно грунта Луны, вычтите ещё
   вращение Луны (на экваторе 4,6 м/с): на поверхности `|v_moon|` = 4,6 м/с, а не 0.
1. **На границе этапов точка повторяется**: последняя точка этапа и первая точка следующего
   имеют одинаковый `t_s` (6 таких пар). На манёврах (`tli`, `loi`, `doi`) у них **разные скорости**
   (до и после импульса), положение одинаковое. Не удаляйте эти дубли бездумно: при
   интерполяции интервал между ними нулевой, и делить на `Δt = 0` нельзя.
2. **Импульсы мгновенные**: скорость скачком меняется на `delta_v`. Траектория при этом непрерывна,
   с изломом.
3. **Шаг неравномерный**: от 1 с до 300 с. Для плавной анимации интерполируйте; см. «Рецепты».
4. **Масштабы очень разные**: радиус Земли 6378 км, расстояние до Луны ~370 000 км, орбита у Луны
   на 100 км над поверхностью. Для сцены нужны логарифмическая камера, разные виды (у Земли, общий,
   у Луны) или единица сцены «1 = 1000 км» с float64 до последнего шага. В float32 точность на
   расстоянии Луны ~0,03 км, этого хватает для показа, но не для расчётов.
5. **Вблизи Луны рисуйте от центра Луны** (`r_moon`): разность `r − moon_r` больших чисел теряет
   точность, а `r_moon` записан напрямую.
6. **Округление**: координаты до 1 м (3 знака после запятой в км), скорости до 1 мм/с,
   кватернионы до 12 знаков.
7. **Этап `terminal`** не моделируется двигателем: это заход и досадка, заданные как запас времени
   (185 с). Торможение кончается в ~15 м над точкой со скоростью несколько м/с; первые ~7 с точки
   плавно (сплайн в осях Луны, без скачка на стыке) доводят аппарат до места посадки, остальное
   время он стоит на поверхности и вращается вместе с Луной.
8. **Ориентации самого аппарата в файле нет** — только положение и скорость. Для показа можно
   направить ось аппарата по скорости (или против неё на торможении).

## Рецепты (Python)

### Загрузка

import json, numpy as np

doc = json.load(open("trajectory-2026-11-15T120738Z.json", encoding="utf-8"))

S = tr["samples"]

# Скорость для показа: у Луны — относительно Луны, иначе — относительно Земли
speed = np.array([np.linalg.norm(s["v_moon"] if "v_moon" in s else s["v"]) for s in S])  # км/с

```

Время UTC из строки: `datetime.strptime(s["t"][:26], "%Y-%m-%dT%H:%M:%S.%f")` (Python держит
только 6 знаков дробной части, поэтому строка обрезается) или `start_utc + timedelta(seconds=t_s)`.

### Поворот кватернионом

```python
def rotate(q, vec):            # body -> J2000
    w, x, y, z = q
    u = np.array([x, y, z]); vec = np.asarray(vec, float)
    t = 2.0 * np.cross(u, vec)
    return vec + w * t + np.cross(u, t)

def rotate_inv(q, vec):        # J2000 -> body
    w, x, y, z = q
    return rotate([w, -x, -y, -z], vec)

# Проверка: стол космодрома в момент старта
e0 = ev["launch"]
print(rotate(e0["earth_q"], tr["spaceport"]["body_fixed_km"]), e0["r"])   # совпадают до ~3 м
# Проверка: место посадки в момент касания
e1 = ev["touchdown"]
print(rotate(e1["moon_q"], doc["landing_site"]["body_fixed_km"]), e1["r_moon"])  # до ~1 м
```

### Вращение тел для каждого кадра

- **Земля**: в `ascent`/`parking_orbit` есть `earth_q` в каждой точке. Дальше вращение можно
  экстраполировать: поворот вокруг оси z ITRF со скоростью 7,2921159·10⁻⁵ рад/с от последнего
  известного кватерниона (`q(t) = q0 · Rz(ω·(t − t0))`). Прецессией за 3 суток можно пренебречь.
- **Луна**: в `lunar_orbit` и дальше `moon_q` есть в каждой точке; на перелёте берите `moon_q`
  из событий `tli` и `loi` и интерполируйте сферически (slerp). Луна поворачивается на ~13° в сутки.
- **Солнце**: `sun_dir` в событиях. Направление за 3 суток меняется на ~3°: можно брать ближайшее
  событие или интерполировать.

### Плавная интерполяция между точками

Для точек у одного тела лучше всего кубический сплайн Эрмита по `r` и `v`: он использует обе
величины. Ошибка зависит от шага и кривизны. Сразу после разгона, где шаг 300 с, а аппарат ещё
близко к Земле, она доходит до ~1 км. На большей части перелёта это метры, на шаге 30–60 с —
миллиметры. Если нужна точность выше, на первом часе перелёта берите шаг сплайна меньше или
линейно интерполируйте поправку.

```python
def hermite(t0, r0, v0, t1, r1, v1, tq):
    h = t1 - t0
    s = (tq - t0) / h
    h00, h10 = 2*s**3 - 3*s**2 + 1, s**3 - 2*s**2 + s
    h01, h11 = -2*s**3 + 3*s**2, s**3 - s**2
    return h00*r0 + h10*h*v0 + h01*r1 + h11*h*v1

def position_at(tq):
    i = np.searchsorted(t, tq, side="right") - 1
    i = min(max(i, 0), len(t) - 2)
    while t[i + 1] == t[i]:          # пропустить пару-дубль на границе этапа
        i += 1
    return hermite(t[i], r[i], v[i], t[i+1], r[i+1], v[i+1], tq)
```

- **В `ascent`** на интервале действует тяга, поэтому Эрмит менее точен, но шаг там 1 с, и
  ошибка незаметна.
- **Вблизи Луны** интерполируйте пару `r_moon` + `v_moon` (обе относительно Луны). Если подставить
  в сплайн `v` (скорость относительно Земли) вместе с `r_moon`, ошибка будет километры: скорость
  Луны ~1 км/с. Саму Луну интерполируйте по `moon_r` + `moon_v`.

### Траектория вокруг Луны

```python
near = [s for s in S if "r_moon" in s]
rm = np.array([s["r_moon"] for s in near])        # J2000 от центра Луны

```

Для Three.js / Unity / Blender: переведите км в единицы сцены (например, 1 = 1000 км), J2000
считайте мировой системой. В Three.js ось y смотрит вверх, а в J2000 к северному полюсу
направлена ось z, поэтому нужна перестановка `(x, y, z) → (x, z, −y)`. Кватернионы `[w, x, y, z]`
переведите в порядок движка (в Three.js `new Quaternion(x, y, z, w)`) с той же перестановкой осей.

## Проверки целостности (для уверенности, что файл прочитан правильно)

- `|start.r|` ≈ 6373 км (стол на поверхности Земли на широте 28,6°).
- `|end.r_moon|` ≈ 1736,35 км = 1737,4 − 1,046.
- В `parking_orbit` `|r|` ≈ 6553–6563 км (185 км над эллипсоидом; расстояние от центра меняется
  с широтой из-за сплюснутости Земли); в `lunar_orbit` `|r_moon|` ≈ 1835,5–1837,4 км (98–100 км).
- Скачок скорости в `tli` по модулю ≈ 3,186 км/с, `|delta_v|` = тому же.
- `r_moon ≈ r − moon_r` с точностью до метров; `v = moon_v + v_moon` с точностью до ~2 мм/с.
- В `lunar_orbit` `|v_moon|` = 1,633–1,635 км/с, а `|v|` = 0,63–2,64 км/с (см. особенность 0).
- В `terminal` `|v_moon|` в конце = 4,6 м/с (вращение Луны на широте 5°).
- `t_s` не убывает; равные соседние значения только на границах этапов.

## Откуда данные (для понимания точности)

- **Подъём**: численная модель ракеты по ступеням — тяга с учётом давления воздуха, атмосфера
  US Standard 1976, J2 и вращение Земли, гравитационный разворот, затем замкнутое наведение.
  Часть параметров ракеты — допущения (см. `notes`).
- **Перелёт**: интегрирование Дормана — Принса 5(4), силы — Земля с J2, Луна, Солнце.
  Эфемериды DE440.
- **У Луны**: поле тяготения GRAIL GL0660B до степени 60 (масконы), Земля, Солнце.
- **Торможение**: моделирование с точечной Луной и её вращением. Заход и вертикальный спуск
  (`terminal`) заданы как запас времени по данным Apollo.
- **Манёвры**: мгновенные импульсы.
