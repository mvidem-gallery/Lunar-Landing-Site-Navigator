# Lunar Horizon

Browser-based, lunar mission illumination and Earth visibility research prototype. English interface. A worker proxies NASA/JPL Horizons; the client renders real LOLA elevation data using Three.js and computes the topographic horizon in a Web Worker.

## Run

Node 22+: `npm run dev`; open the advertised local port. The local server reuses successful terrain, imagery and JPL responses from .lunar-cache across restarts. A first request for a new site or date still depends on the external data archives. On localhost, eligible stereo and LOLA elevation requests fetch just the selected columns via grouped byte ranges when the archive supports them, with the original full-row request as a fallback. No dependency installation needed: Three.js 0.170.0 is vendored under assets (MIT). `npm test` runs geometry and integration tests; `npm run build` produces a self-contained deployable worker.

## Inputs

Planetocentric latitude −90 to 90 degrees; east-positive longitude −180 to 180. Observer height 0.1–100 m above DEM. The view can rise an additional 0–10 km without changing the mission calculations. UTC start/end 2000–2100, mission duration up to 365 days. The requested step is increased when necessary to keep the number of readings below 15,000. The lander is an illustrative model aligned with the rendered terrain at the landing coordinates. Mission suitability compares the longest continuous modeled darkness with the user’s limit. For an unsuitable mission, the planner searches the following 365 days for the earliest feasible UTC start of the same duration. The estimate assumes a charged battery on landing and restored autonomy after direct sunlight returns. Query parameters `lat`, `lon`, `height`, `start`, `end` prefill the form; dates use `YYYY-MM-DDTHH:mm`. This is the future integration entry point for the external site.

## Data and method

- Mid-latitude elevation: SLDEM2015 (NASA LOLA + Kaguya stereo), 512 pixels/degree (~60 m), within about 18 km north/south of the observer for |latitude| ≤59.3°. Float32 kilometer samples are streamed from the PDS archive, cropped and converted to meters. This dataset takes priority over the smaller-sampled but sparse LOLA-only raster. Archive failures fall back to LOLA.
- Detailed elevation: NASA LOLA LDEM_1024 (~30 m sample spacing) within about 2.7 km north and south of the landing site where available. The 30 m layer is skipped within 0.3° of the poles to bound requests; the polar and lower-resolution layers cover those regions. The local mesh samples at around 20 m and coarsens toward the horizon. NASA LOLA LDEM_256, about 118 m along meridians around the selected point, and LDEM_64 (about 474 m) for the surroundings. The server reads a byte range for the selected latitude band and returns the local subset. The browser falls back to the bundled map when NASA PDS is unavailable.
- Global elevation: NASA PDS LOLA LDEM_16, averaged to 8 pixels/degree and rounded to meters. The grid is approximately 3.79 km along meridians and wraps at 180° longitude. See scripts/prepare-global-dem.py.
- NASA PGDA product 90: https://pgda.gsfc.nasa.gov/products/90
- DEM: https://pgda.gsfc.nasa.gov/data/LOLA_20mpp/LDEM_80S_20MPP_ADJ.TIF
- `data/terrain.bin`: float32 little endian, 2000×2000, 20 m raster within ±20 km of the south pole. Metadata in matching JSON.
- `data/far.bin`: 950×950 resampled DEM, 640 m raster, ±304 km polar square. Bilinear resampling, not a conservative maximum-height pyramid.
- DEM generation scripts require Python rasterio, tifffile and numpy, and internet. Near/far data are derived from the same NASA product family. Both use MOON_ME/DE421, sphere radius 1,737,400 m.
- API: https://ssd-api.jpl.nasa.gov/doc/horizons.html . Targets 10/399, observer `coord@301`, geodetic east longitude/latitude and DEM altitude+eye height; quantities 4,13,20. Serial requests and browser session caching. Apparent azimuth/elevation in airless lunar coordinates. No fabricated fallback if unavailable.
- Horizon sampled at 0.5° azimuth; Distances up to 250 km, with 10 m increments near the high-resolution polar site, 320 m in the regional mode and 950 m for the global grid. Exact spherical position transform includes lunar curvature. DEM sample bilinear interpolation.
- Local normal estimated with differences scaled to the available DEM. Sun illuminates when its center is above terrain and incidence <90°. Earth visible when disk center clears terrain. This does not model partial disk visibility, solar eclipses by Earth, stations, antenna patterns, radio link budgets, boulders, or subpixel terrain.
- When a new site is calculated, a lightweight mesh from the bundled DEM previews the terrain while detailed data downloads. Mission calculations use the final terrain and horizon. The 3D mesh extends approximately 490 km along each local axis, using eight concentric grids with near-square triangles, explicitly matched LOD edges and DEM-derived normals. Sun and Earth disc radii use the exact angular silhouette relation r = d × sin(angular diameter / 2), with JPL angular diameters and camera parallax. Numeric angular diameters are displayed. The visible Sun has a decorative glow. Optional NASA Moon Trek LRO WAC imagery (~100 m native pixels) is projected geodetically onto the terrain with mipmaps and anisotropic filtering. The photo mosaic has fixed acquisition shadows, unrelated to mission lighting; turn it off for geometry-only shading. Near images blend smoothly into a wider, lower-resolution photo mosaic. Equatorial imagery uses 16 near tiles at zoom 8 and 64 overview tiles at zoom 4. Above 75° latitude, a continuous polar stereographic projection uses the NASA north/south WAC mosaics (16 zoom-5 near tiles and 16 zoom-2 overview tiles; near served spacing about 268 m). PNG nodata is transparent. Tiles appear as they arrive. Missing detail uses overview imagery when available, with shaded terrain visible in remaining gaps. The tile queue stops waiting after 15 seconds. The relief-lighting button replaces solar shading with fixed angled lighting and a soft fill while preserving the numerical calculations. Elevated sky views use an approximate spherical horizon and scene depth occlusion. Lighting is illustrative directional shading; it does not render distant terrain shadow maps. Numerical horizon status is authoritative within model limits. Earth has a NASA Blue Marble globe with JPL orientation and phase. HYG catalogue stars rotate with the IAU lunar orientation model. See assets/SKY-CREDITS.md.
- Ephemerides interpolated linearly (wrapped azimuth), visibility transition durations estimated with linear crossings between samples. Short events can be missed. Overlap duration intersects each pair of positive linear-margin time intervals. Not flight-qualified, no independent SPICE benchmark yet.
- Signal delay is geometric observer-to-Earth-center distance / 299,792.458 km/s, not total telecom latency.

## Source layout

`src/index.html`, `style.css`, `app.js`: interface and Three.js scene. `math.js`: shared spherical geometry and numerical routines. `terrain-worker.js`: horizon and terrain generation. `server.js`: validated Horizons proxy. `scripts/bundle.mjs`: embeds assets into worker/index.js and builds deployment output. `scripts/dev.mjs`: local preview server. `tests/`: focused numerical tests.

Next accuracy milestones: regional 5 m DEM near observer, conservative far-field maxima, adaptive horizon angular sampling, disk-fraction and eclipse model, sub-sample transition refinement, SPICE independent validation.
